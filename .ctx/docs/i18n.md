# Internationalization (i18n)

## What It Does
Provides multi-language support for the app UI using i18next. Three locales are supported — English (en), Spanish (es), and German (de) — with Spanish as the default and English as the fallback.

## Main Files
- `src/i18n/index.ts` — Initializes i18next with react-i18next, registers all three locale bundles, sets default and fallback languages
- `src/i18n/locales/en.json` — English translations
- `src/i18n/locales/es.json` — Spanish translations
- `src/i18n/locales/de.json` — German translations

## Flow
1. `index.ts` is imported once at app startup; i18next is configured with all locale resources
2. React components call `useTranslation()` (from react-i18next) and access keys via `t('some.key')`
3. The active language can be changed at runtime (e.g. from Settings); i18next swaps translations without a page reload

## Translation Key Structure
All locale files share the same key hierarchy:

| Namespace | Purpose |
|-----------|---------|
| `app` | App name and status labels (idle, recording, processing, editing, success, error) |
| `settings` | All settings-page labels: API key, hotkeys, behavior toggles, audio, overlay, model selection; grouped into sections (`api`, `hotkeys`, `behavior`, `audio`, `overlay`, `interface`) |
| `presets` | Presets/transform page: input placeholder, custom prompt, apply buttons, result area, copy feedback |
| `tabs` | Main navigation tab labels (Transcription, Presets, Settings) |
| `languages` | Human-readable language names shown in the language picker (es, en, de, auto) |

## Adding a New Language
1. Create `src/i18n/locales/<code>.json` mirroring the key structure of `en.json`
2. Import it in `index.ts` and add it to the `resources` object
3. Add the new code to the `languages` namespace in all existing locale files

See [`config_and_store.md`](config_and_store.md) for how the selected UI language is persisted in the config store.
